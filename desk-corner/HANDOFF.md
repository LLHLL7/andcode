## 1. 项目是什么

一个单文件 HTML 互动作品（约 2MB）：用户自己的书桌和书架，做成可探索的解谜游戏。现阶段把它当"展板"，**先把内容和玩法定下来，以后整体复刻到 Godot**。

**整体结构（用户的设计）：**
- 书桌上的电脑是"破解核心"，需要 **6 个密码**，密码散落在书架各处的 6 个关卡里。
- 6 个关卡对应用户的 6 个侧面：

| 关卡 | 主题 | 状态 | 密码 |
|---|---|---|---|
| 洗衣机故事（左书架；含 8 张分镜卡的分镜排序谜题、3D 洗衣工厂 UNIT 14 等，都围绕这个洗衣机故事） | 创作 / 影视专业 | 已有 | **E** |
| 蓝晒 | 记忆 | **刚完成** | **L** |
| 音乐 | 成长 | 未做 | — |
| 牛仔裤 | 痕迹 | 未做 | — |
| 痘痘 | 自我凝视 | 未做 | — |
| 娱乐 | 游戏 | 未做 | — |

> 注：分镜谜题是洗衣机故事关卡的一部分，它给出的密码原来也是 L，已按用户要求改成 **E**（片尾大字 `#bigL`、最后一格、toast 都改了）。所以洗衣机关 = E，蓝晒关 = L，一共 6 关、6 个密码。"破解核心"电脑的 6 位密码输入还没做。

## 2. 和用户合作的规则（很重要）

- **全程中文**沟通，用户在电脑上用 Chrome 测（手机先不管）。
- **构图不要动**，除非用户明确要求；**光影、形状只在用户要求时改**。
- **透视细节必须实时**，不能冻结。
- **不能有可察觉的模糊**：用户对模糊非常敏感，被否过好几次。
- 性能：用户对掉帧敏感。但目前用户说"**先做内容，透视和性能优化先不管**"，以后到 Godot 里再解决。
- 解谜设计：**失败可以没反应，最好不要让玩家重来**；参考其他游戏，卡住时给渐进提示。
- 交互一致性：每个可交互物品都要有悬停反馈（抬起，或放大加黄色光边 `#f6d58a`）、单一名字标签、点开有查看页。放回时要"弹一下"。
- 每次做完：截图自查，跑回归测试，发布，再用中文简要汇报做了什么、怎么验证的，以及需要用户确认的点。

## 3. 代码结构速览（index.html）

文件外层套了一层 doctype（artifact 包装），真正的文档在里面。主要有两个 `<script>`，第二个是主体。

### 3.1 场景渲染
- **相机 / 分镜**：`TG[z]` 是各区域的目标相机：0 全景，1 左书架，2 右书架，3 置物架（黑铁架），5 显示器，6 台灯，7 右侧柜板。`zoom(z)` 负责推近 / 拉远，`window.__zoom(z)` 可以在测试里调用。
- **`render0(c0,cm)`**：每帧做透视投影。
  - 先画 3 张 canvas（`cv0` 背景、`cv1` 中层、`cv2` 前景），由 `SCENE` 数组驱动，`['s','R']` 和 `['s','C']` 是切换画布的分隔标记。
  - 再把所有 DOM 物品（`IT` 列表，分布在 `#stage` 左书架、`#stage2` 右书架、`.zn .zsc` 置物架、`#stageF`）按 3D 坐标投影，设置 `translate`、`scale` 和各种透视细节（书侧面、圆柱等）。
- **SCENE 记录类型**：
  - 基础：`p` 多边形、`l` 线、`b` 盒子、`P` 圆柱、`O`、`S`、`g`。
  - 后来加的：`H`、`T`（遮光罩花瓣）、`W`（碗）、`R` / `RL`（输液瓶）、`FAN`。
  - `OBJ`：动态 3D 物体，渲染时调用 `O3[name].rec(L)` 生成记录。
- **`O3` 动态 3D 物体**：
  - 遮光罩 `hood`、生理盐水瓶 `bottle`、夹式风扇 `fan`。
  - 台灯 `lamp`、台灯下桌面上的物品 `desk`（这两个都在蓝晒模块里）。
  - 字段含义：`glow:1` 悬停时放大加黄光边，`ns` 前几条记录不参与发光，`pv` 放大中心点。悬停动画用 `o3go(o,target)`。
- **`VOL`**：物品深度和透视细节的配置；`setup()` 生成 `IT`。
- **LOD**：碗、瓶、遮光罩按屏幕尺寸自动调细分（`LOD()`），网格用 `MK()` 缓存。

### 3.2 性能相关（已做，别回退）
- 推近 / 拉远时，物品交给显卡图层（`.mv` 类）。推近途中按约 1.2 倍的放大间隔，用 `.nr` 类分批刷新清晰度；只刷新"终点仍可见"的物品（`o._ev`）。
- 画布分辨率按镜头速度动态调整（`setQ(f)`）：首尾 100%，中段最快时 72%。
- 鼠标悬停到区域上时提前把物品交给显卡（`PRE`）。
- 画面外的物品和多边形会被剔除（culling）；画布按窗口大小裁剪（`CW` / `CHF` / `OXC` / `OYC`）。
- 自由视角（空格开关）移动时不降分辨率。

### 3.3 交互保护
- 推近过程中和结束后 0.45 秒内，点击不会打开物品（`ZBLK` / `PDZ`）。
- 进入近景后，鼠标真正移动之前物品不响应悬停（`body.nohov`）。

### 3.4 道具 / 对话
- **物品查看页**：`OV[key]` 定义 `{n 名称, d 描述, big SVG, acts:[[按钮, 文本或函数, 粒子效果]], item:[按钮下标, 道具key]}`。`look(key, el)` 打开，`shut()` 关闭。
- **道具**：`ITEM[k] = {k, n, icon, open, big:false}`；`giveItem(k)` 获得（带飞入动画），`items` 是已持有列表，`invUI()` 重绘道具栏。道具栏已从 6 格扩到 **12 格**。
- **右书架物品**定义在 `const A={...}`（格式 `[viewBox, 名, 描述, svg, acts]`），置物架物品在另一个 `A` 里（例如 `sjBtl` = 两瓶深色的瓶子）。

### 3.5 坑（踩过的）
- 渲染、相机那一块代码在**块级作用域**里。蓝晒模块追加在 script 末尾，访问不到这些变量，所以在 `window.__zoom=zoom` 后面导出了：`window.O3`、`o3go`、`hov`、`RHK`（每帧回调钩子）、`__rr()`（安全地重画一帧）。
- **类名冲突**：页面里原本就有 `.dsk`（旧桌面背景），所以桌面点击区改名为 `.cydk`。新加类名前先 grep 一下有没有重名。
- 通用的 `.it:hover` 会让元素抬起、旋转，`.lb` 会显示大标签。自定义点击区要加 `transform:none!important`，并把 `.lb` 隐藏。
- Python 正则在这个 2MB 文件上容易卡死（灾难性回溯），尽量用 `str.find` 加切片。
- 测试环境没有显卡（swiftshader），**测不出真实帧率**，只能看功能和截图。

## 4. 蓝晒关卡（刚完成，代码在 `cyan_mod.js` / `cyan_css.css`，已内嵌进 index.html 末尾）

### 4.1 剧情
用户大一下出去拍摄影作业，爬山时扭伤摔倒，膝盖做了手术、打了钉子；这是术后拍的片子，钉子隐约可见。大三觉得好玩，把它晒成了蓝色。片子右上角的 **L**（X 光左侧方位标记）就是密码。用户提供的实拍蓝晒照片是成品画法的参考。

### 4.2 流程

**1. 找材料（共 7 样）**

| 材料 | 位置 | 拿取方式 |
|---|---|---|
| A 液、B 液 | 置物架黑铁架上「两瓶深色的瓶子」 | 紫色是 A，红色是 B；标签被撕掉，瓶底马克笔写着字母；拿走后对应瓶子从架上消失 |
| 毛刷 | 「蓝晒印象」纸盒（右书架顶夹缝） | 「拿出毛刷」；盒里还有说明书、巴掌大的相纸、晒好的小画，**没有药水** |
| 片子 | 右书架「卷起来的海报」筒 | 先「往里看」，再「抽出来」；片子是黑灰色、严重失真、看不出部位的 |
| 白纸 | 右书架顶夹缝 | 原有的拾取 |
| 白色小碗 | 遮光罩里 | 「拿起白色小碗」；拿走后 3D 场景里的碗和碗足都会消失 |
| 生理盐水 | 右书架 | 「收起来」进道具栏，3D 瓶子随之消失 |

**2. 台灯**

显示器右边的圆盘灯头、弯杆台灯（按用户照片做的）。在场景里点一下就循环切换 黄 → 白 → 紫，全屋光色跟着变（`#lit` / `#litg` 叠加层）；悬停有黄光边和"台灯"标签。

**3. 摆到灯下**

从道具栏**拖**到台灯下的桌面（拖动时出现虚线放置框），东西会画在桌上。悬停这堆东西时整体发光、显示"台灯下"，点击打开蓝晒台。蓝晒台打开时也可以直接把道具拖进去（此时道具栏在蓝晒台上层）。

**4. 蓝晒台**（`#cy` 全屏面板，SVG 1000×620）

顶部 6 个圆点对应说明书的 6 步：
1. 点 A、B 瓶，倒进碗里。
2. 点毛刷，调匀。
3. 按住拖动刷满整张纸（6×8 格覆盖 44 格即算完成）。
4. 点纸盒，避光风干（钟表动画）。
5. 点片子，压到纸上；台灯换成紫光后自动曝光，约 4 秒。
6. 点片子拿开，再点盐水瓶冲洗：黄水流走，纸变蓝，显出骨头、钉子和 L。

**5. 结尾**

成品图加逐行回忆文字，最后一行"片子的右上角，有一个字母：L"。点「收好」后获得道具「蓝晒·膝盖」，并提示 `密码：L`。

**设计原则**：没有失败重来。顺序不对时只轻轻晃一下或给一句话；卡住 11 秒后用金色字给出说明书对应步骤的提示。

### 4.3 关键代码点
- 状态对象 `CY = {has:{...}, a, b, mix, load, coat, wet, dry, film, exp, expd, lift, rin, done}`。
- 材料表 `MAT = {A, B, brush, bowl, paper, ct, saline}`。
- 台灯模式 `window.LMODE`（`'Y'|'W'|'U'`），切换函数 `setLamp(m)` / `cycle()`。
- 每帧钩子 `RHK.push(...)` 负责台灯、桌面点击区的投影定位，以及灯光叠加层中心。
- 膝盖影像 `KN(palette)` 只有一套形状，配色有三套：`PAL.film`（片子）、`PAL.expo`（曝光中）、`PAL.print`（成品）；成品图函数 `printSVG()`。
- 遮光罩和盐水瓶关掉查看页后的弹回动画：`bounce(o)`，由 MutationObserver 监听 `out` 类的移除来触发。
- 测试入口：`window.__cy`、`__openCy()`、`__setLamp(m)`、`__cyPlace(k,'desk'|'bench')`。

## 6. 测试（`tests/`）

依赖 Playwright 和 Chromium（cloud 环境里有 `/opt/node-tools/node_modules` 和 `/opt/pw-browsers`）：

```bash
mkdir -p shots   # 测试脚本会把截图写到当前目录的 shots/
export NODE_PATH=/opt/node-tools/node_modules
S=$PWD/desk-corner/index.html
node desk-corner/tests/errs.js $S          # 加载时有没有报错
node desk-corner/tests/cyplay2.js $S       # 蓝晒关卡完整通关（拾取→拖到桌面→蓝晒台6步→成品）
node desk-corner/tests/abtest.js $S        # 铁架上 A/B 两瓶的拾取
node desk-corner/tests/benchdrag2.js $S    # 直接拖进已打开的蓝晒台
node desk-corner/tests/fix3.js $S          # 单标签、桌面悬停、盐水瓶弹回
node desk-corner/tests/hz.js $S; node desk-corner/tests/hz2.js $S   # 全景点区域进近景（含自由视角）
node desk-corner/tests/dbl2.js $S          # 推近时 / 刚结束时的连点不误开物品
node desk-corner/tests/nohov.js $S         # 进近景后鼠标不动，物品不弹起
node desk-corner/tests/o3test.js $S shots/o3   # 遮光罩、盐水瓶、风扇的查看页
node desk-corner/tests/collect2.js $S shots/col  # 手机、白纸、说明书的拾取
node desk-corner/tests/zblur.js $S shots/zb 600  # 推近途中截图（看清晰度）
```

截图验证时可以用 PIL 拼图对比；做画面改动时，和上一版逐像素对比（`numpy` 求差值），确认没有意外改动。
